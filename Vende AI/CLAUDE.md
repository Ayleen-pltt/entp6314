# CLAUDE.md: VendeAI

Rules for everything in this folder. Read `prd.md` for what to build and `design.md` for how it looks.

## How to work

- Build one milestone at a time, in the order in `prd.md`. Do not start the next milestone until the user says so.
- After each milestone, check the result against the test case in `prd.md` (Spanish and Portuguese messages) and say whether every number matches.

## Stack

- **App:** plain HTML, CSS and JavaScript in one file (`app/index.html`). No framework and no build step. The only package (`package.json`) is `@google/genai`, used by the server function.
- **Web and installable app (PWA):** the same `app/index.html` works in the browser and installs to the phone's home screen. `app/manifest.webmanifest` (name, colors, icons in `app/icons/`) and `app/sw.js` (offline helper: pages network-first with a 4-second fallback to the saved copy; `tokens.css`, fonts, icons and `app/vendor/` saved; `/api/ai` and Supabase never stored). Bump `VERSION` in `sw.js` with each release. The install card uses the browser's install prompt on Android and computers, and explains Share > Add to Home Screen on iPhone. Google Play / App Store packaging can wrap this same app later.
- **Hosting:** Vercel, project `vendeai` (https://vendeai-pi.vercel.app). `vercel.json` sends `/` to `/landing/` (the front door, with one call to action: "Empieza gratis" → `/app/`; ES/PT/EN switch that saves the choice in `vendeai_preferencias.lang`, so the app opens in the same language), and `.vercelignore` keeps internal documents (`*.md`, `strategy/`, `probes/`, `tools/`) off the site. Site files at the root: `404.html` (Vercel shows it for any missing page), `robots.txt`, `sitemap.xml` (update `lastmod` when a page changes) and `og-image.png` (1200×630 share preview used by the `og:image` tags). Legal pages: edit the `.md`, then run `node tools/legal-pages.cjs` to rebuild the `.html`.
- **Vercel Web Analytics:** the plain-HTML script tag in the `<head>` of `app/index.html`, loading `/_vercel/insights/script.js` from the same site. No `@vercel/analytics` package. It counts page views without cookies and is disclosed in `legal/politica-de-cookies.md` and `legal/politica-de-privacidad.md`.
- **Google Gemini:** model `gemini-3.5-flash` through the `@google/genai` package, called only from the Vercel Function `api/ai.js` (`POST /api/ai`). The key is `GEMINI_API_KEY`: in `.env.local` on this computer and in the Vercel project's environment variables online. It is never sent to the browser. Four tasks: `voice` writes a voice note as text (the microphone on Anotar records up to 60 seconds at 24 kbps with the browser's MediaRecorder; the audio goes to `POST /api/ai`, is never saved, and the text then goes through `sale` and the confirm card; free plan 10 notes a month, counted in `data.voice`, on the phone for now like the plan, so it is not yet proof against tampering), `sale` reads a sale message into fields, `advice` rewrites the assistant's sentences, and `plan` suggests one of the four plans from the "Tu negocio" answers (the app accepts it only if the only number is that plan's price; one result is kept per set of answers in `data.planAI`). The app checks every answer (numbers must come from the message or from the app's own sentence) and falls back to its built-in rules when the AI is slow (9 s on the server, 12 s in the browser), busy, over its free limit (20 requests a day on the free tier) or unreachable. Local testing: `node dev-server.mjs` (the `vendeai` preview), which serves the pages and runs `api/ai.js` like Vercel does.
- **Stripe (sandbox only):** Stripe Checkout, the payment page Stripe hosts, for the three paid plans in `prd.md` (Standard US$5.99, Medium 9.99, Business 19.99 a month, subscriptions; Freedom is free). Server code in `api/checkout.js`: `POST /api/checkout` creates a Checkout Session and returns its Stripe address; `GET /api/checkout?session_id=` asks Stripe whether it was paid. Keys `STRIPE_PUBLISHABLE_KEY` and `STRIPE_SECRET_KEY` in `.env.local` (and Vercel); the secret key never reaches the browser. The function refuses to run unless both are test keys (`pk_test_` / `sk_test_`); any `pk_live` or `sk_live` key stops it. Stripe returns the seller to `pago/exito.html` (checks the payment with our server, then leaves `vendeai_pago` in localStorage for the app to pick up as `data.plan`) or `pago/cancelado.html`. The plan is saved on the account by the webhook `api/stripe-webhook.js` (`POST /api/stripe-webhook`): `POST /api/checkout` gets the seller's Supabase token and puts her user id on the session (`client_reference_id`, `metadata.user_id`); the webhook checks Stripe's signature with `STRIPE_WEBHOOK_SECRET` (whsec_, 5-minute limit), refuses live events, and writes `app_metadata.plan` (`{ tier, status, subscription, at }`, which only the server can write) with `SUPABASE_SECRET_KEY`. Events: `checkout.session.completed` (paid), `customer.subscription.updated` (active, trialing and past_due keep the tier; anything else is Freedom) and `customer.subscription.deleted` (Freedom). The app reads it on sign-in (`planFromAccount`, `refreshPlan`): the account wins unless the phone's own payment note is newer. The webhook endpoint is made in the Stripe dashboard (test mode) for https://vendeai-pi.vercel.app/api/stripe-webhook with those three events.
- **Supabase Auth:** email and password only, project `Vende AI` (`SUPABASE_URL` and `SUPABASE_PUBLISHABLE_KEY` in `.env.local` and in Vercel; the secret key only in server code that needs it, never sent to the browser; `api/config.js` refuses it). `api/config.js` (`GET /api/config`) hands the page the URL and publishable key; the page uses the bundled `app/vendor/supabase.js` (supabase-js 2.118.0). Supabase stores passwords hashed (bcrypt); the session lives in the browser's localStorage (`sb-...` key) and renews itself; each account's app data is kept under `vendeai_datos:<user id>`. Not signed in = only the sign-up / sign-in / reset screens. Sign-up needs email confirmation; Supabase Site URL and Redirect URLs are `https://vendeai-pi.vercel.app/app/` (add `http://localhost:5180/app/` for local testing). Database: run `supabase/migrations/0001_initial_schema.sql`, then `0002_auth_and_rls.sql`, `0003_storage.sql` and `0004_seller_data.sql` (also split in `supabase/0002-in-parts/` for when the SQL Editor fails on the long file): a trigger creates the seller row and the two consents at sign-up, every table allows a signed-in user only their own rows, guest accounts are blocked, and the public key reaches no table or function.
- **Resend (email, test mode):** sent only from server code through Resend's REST API (no package). `api/_email.js` is the shared helper (the leading `_` keeps it from being a page): `sendEmail()` never throws, and the brand templates are in es/pt/en. Two emails: a **welcome** after the first sign-in (`POST /api/welcome`: the page sends its Supabase session token, the server asks Supabase who it is, sends once and marks `user_metadata.welcome_sent`), and a **receipt** after paying (sent by `GET /api/checkout` the first time it sees a paid session, then marked `metadata.receipt_sent` in Stripe). Keys: `RESEND_API_KEY` and `RESEND_TEST_TO` in `.env.local` and Vercel. No verified domain yet, so every email is sent from `onboarding@resend.dev` to `RESEND_TEST_TO` only. To email real sellers: verify a domain in Resend, set `RESEND_FROM` (for example `VendeAI <hola@tudominio.com>`) and remove `RESEND_TEST_TO`. If sending fails, the app carries on and shows nothing.
- **Marketing emails (Resend):** templates in `api/_marketing.js` (es/pt/en): **news** (edit `EDITION` for each send; everyone who opted in), **upgrade** (Freedom sellers: why Standard pays for itself) and **tips** (paying sellers: how to use their plan, plus what the next plan adds; Business gets tips only). Sent only from this computer with `node tools/send-campaign.mjs` (`preview`, `sample`, `news`, `upgrade`, `tips`, add `--send`), which reads the account list with `SUPABASE_SECRET_KEY` (in `.env.local`, and in Vercel only for `api/stripe-webhook.js`; never in the browser). Only sellers who ticked the optional sign-up box (`user_metadata.marketing === true`) get them; the plan used to pick the email is `user_metadata.plan`, saved by the app after paying (it never unlocks anything). Every email ends with a "Dejar de recibirlos" link to `/app/#email-off`; the footer button "Novedades por email" turns them on or off. Upgrade emails link to `/app/#planes`.
- **Supabase Storage (files):** three private buckets made in the dashboard: `comprobantes` (payment proof), `catalogos` (catalogs and product photos) and `stock` (supplier lists, invoices, stock sheets). The "Tus archivos" panel on "Todo en un lugar" uploads straight from the browser with the seller's own session (no server code, no secret key), lists all three buckets, opens a file through a 60-second signed link, and deletes. Each file is saved as `<bucket>/<user id>/<time>-<name>`. `supabase/migrations/0003_storage.sql` keeps the buckets private, makes Storage itself refuse anything that is not JPG, PNG or PDF (plus Excel .xlsx/.xls in `stock`, where sellers keep their stock sheets) or is over 5 MB, and adds one rule on `storage.objects`: a signed-in, non-guest seller can list, open, add or delete only inside the folder named with their own user id. The app checks size and the file's first bytes first, so it can explain the refusal in plain words. Signed out or in demo mode the panel only says to sign in.
- **Open-Meteo (weather, no key):** the header's top-left corner shows the live temperature in °C for the main city of the seller's country (`data.profile.country`: CDMX, Bogotá, Lima, Buenos Aires, Santiago, São Paulo), never the phone's location. The page calls our own `api/weather.js` (`GET /api/weather?country=PE` → `{ city, temp }`), which asks `api.open-meteo.com/v1/forecast` for `current=temperature_2m` with a 4-second limit; Vercel's cache keeps each country's answer 15 minutes (`s-maxage=900`). The app asks on opening, every 30 minutes while on screen and when the seller comes back; after 6 seconds or any error it shows "El clima no cargó, ya volverá" and nothing else changes. Open-Meteo's free API is for non-commercial use: VendeAI needs its paid plan (or another provider) before charging real sellers.
- **Demo mode:** while `/api/config` has no valid Supabase settings (it returns `null`), the app skips sign-in: the seller gives a name, country and the two acceptances, and data stays on that phone (`vendeai_datos:demo`). Real Supabase values in Vercel switch sign-in on by themselves.
- **Data (phone first, then sync):** the whole notebook (sales, products, customers, payments due, "Tu negocio", change log) is saved in the browser's `localStorage` at once (per account) and uploaded a moment later to the Supabase table `seller_data` (`supabase/migrations/0004_seller_data.sql`: one row per seller, `data` jsonb under 2 MB, `rev` revision, own-row RLS, no guests). `saveData()` marks a change and uploads after 1.5 s; the app also syncs on sign-in, when the signal comes back, when the seller returns to the app, and before signing out. Each upload names the revision it started from (`update ... where rev = base`); if another phone saved first, `mergeCopies()` takes the account copy as the base, adds this phone's new sales, products, customers and log lines, keeps the furthest state of a shared sale (undone, more installments received) and corrects stock for them. A phone that never synced is always merged, never overwritten. Progress per account lives in `vendeai_sync:<user id>` (`{ rev, n, done }`). The footer says whether sales are saved to the account, waiting, offline or failed (retry every 30 s). If the table doesn't exist yet the app stays phone-only and says nothing. The row-by-row tables in 0001 (sales, sale_items, payments…) are not filled yet: their triggers change stock themselves, which would fight the app's own count. "Reiniciar datos de prueba" also clears the account copy.

## Technical limits (prototype)

- The app is one file, `app/index.html`, holding all HTML, CSS and JavaScript, plus the shared `tokens.css`. It opens by double-clicking it.
- No framework, no build step. Sign-in is Supabase Auth (see Stack). The server code is `api/ai.js`, `api/config.js`, `api/checkout.js`, `api/stripe-webhook.js`, `api/welcome.js` and `api/weather.js`; the browser holds no secret key, and uploads go to Supabase Storage with the seller's own session. The page talks only to its own site (`/api/*` and Vercel Web Analytics), except that "Pagar" sends the seller to Stripe's own payment page. Opened by double-clicking, the AI is unreachable and the app uses its built-in rules. Design tokens live in `tokens.css` at this folder's root, the one shared file every page links. Fonts are self-hosted in `fonts/` (Baloo 2 and DM Sans, SIL Open Font License), never loaded from Google Fonts (see `legal/politica-de-cookies.md`).
- Gemini reads sale messages first; `saleFromAI()` checks its answer. The rule-based `parseSale()` stays as the fallback and fills any field the AI left empty.
- Data lives in `localStorage` under `vendeai_datos` and `vendeai_preferencias`, wrapped in try/catch, with a synced copy in Supabase (`seller_data`) for signed-in sellers. The app must still work without either.
- Every piece of screen text comes from the `I18N` object (`es`, `pt` and `en`). Never write screen text directly in the markup.
- The app does all the math. Money is rounded to cents.

## Look

### Design rules

- Read `design.md` before building or changing any UI.
- Theme tokens live in `tokens.css`. Never hardcode colors or fonts; use the tokens (`var(--primary)`, `var(--muted-foreground)`).
- Before creating a new piece, check `/styleguide/` and reuse or extend what exists.
- New reusable pieces go in `app/index.html`, follow the existing patterns, and get added to `styleguide/index.html`.
- Primary color is only for main actions. Use `--owed`, `--paid` and `--destructive` for status and errors.
- Only use sizes from the type scale in `design.md`. Body text minimum 16px.
- After building UI, check it against `/styleguide/`.

`/styleguide/` (`styleguide/index.html`) is an internal reference, marked noindex. It reads `tokens.css` and the `<style>` of `/app/` when it opens, so it needs the site or `dev-server.mjs`, not a double-click. A new piece must be added to its markup by hand.

All design rules (colors, fonts, layout, buttons and cards, words on screen, emails, accessibility, and the checks before shipping a design change) are in `design.md`. Read it before changing any screen, page or email.
